# 상담사 QnA 샘플 110개

검토일: 2026-10-16. 실제 이용자의 문의나 문의량 순위를 나타내지 않는 교육·안내용 샘플입니다. 기존 이용자가 작성한 질문·답변은 보존합니다.

## 내용과 근거

통신사 공식 FAQ에서 문의 주제를 선정하고, 답변의 실제 기능·메뉴·노출 조건은 현재 스카이라이프 홈페이지 소스와 공식 안내에 맞춰 작성했습니다. 경쟁사 정책·금액·처리기간을 스카이라이프에 적용하지 않았습니다. 개인·사업자, TV·인터넷·모바일을 구분하고 로그인·가입상품 조건, 상담 접수와 처리 완료의 차이를 표시합니다.

원고는 `content/qna-samples.json`에 있습니다. 72개 실제 소스 파일의 경로·줄번호·SHA-256과 82개 공식 URL을 근거로 기록했습니다. 각 문항에는 관련 가이드 기능 ID, 질문 주제 참고 출처(`topic`), 스카이라이프 정책(`skylife-policy`) 또는 기능 경로(`feature`)를 구분합니다. 전체 98개 기능 중 64개와 연결하며, 같은 기능이어도 서로 다른 상품·상황·처리 조건의 질문을 포함합니다.

KT·KT M모바일·SK7모바일·U+유모바일·B world·LG유플러스의 공식 FAQ는 문의 주제 발굴에만 활용했습니다. 실제 답변의 조치 경로는 스카이라이프 소스로 대조했습니다. 출처별 원문을 길게 복제하지 않았으며, 질문은 새로운 샘플 상황으로 작성했습니다.

작성자는 **가이드북 샘플**로 표시합니다. 질문과 답변에 샘플 표시를 넣고 답변에는 홈페이지 및 관련 기능 가이드 링크와 확인 기준일을 붙였습니다. 개별 고객의 계약·요금·처리 가능 여부를 보장하지 않습니다.

## 공유 게시와 보존

`server/qna-publication.cjs`는 서버에 포함된 검토 원고만 Production에서 공유 객체 파일에 게시합니다. 요청자가 임의 내용을 일괄 등록하는 API는 없습니다. 일반 이용자의 쓰기 제한과 소유권 검사는 변경하지 않았습니다. 데이터베이스를 사용하지 않습니다.

ETag 조건부 저장으로 110개 질문과 110개 답변을 한 번에 반영합니다. 중복 게시를 막는 안정된 ID와 개정 번호를 사용하며, 동시에 등록된 사용자 글도 다시 읽어 보존합니다. 샘플 게시 실패 시 부분 반영하지 않고 기존 QnA 조회·작성을 유지하며 준비 중 상태를 표시합니다. Preview는 샘플을 게시하지 않습니다.

샘플에도 누구나 추가 답변을 작성할 수 있습니다. 일반 작성 글의 수정·삭제는 작성 브라우저 권한을 따릅니다. 관리 샘플의 질문과 최초 답변은 GitHub 검토 원고에서 관리하고 임의의 브라우저 소유키를 공개하거나 보관하지 않습니다. 원고 갱신 시 참여자가 추가한 답변을 보존합니다.

## 업데이트

1. `content/qna-samples.json`의 해당 `key`에 질문·답변 및 확인 근거를 수정합니다. 기존 `publicationId`와 `key`는 유지합니다.
2. `revision`을 반드시 증가시키고 검토일을 갱신합니다. 낮은 개정의 이전 배포가 최신 원고를 덮어쓰지 않습니다. 같은 개정 번호로 다른 내용을 게시하면 원고 변경을 보류합니다.
3. 콘텐츠 검증·테스트·브라우저 확인 후 GitHub → Vercel로 배포합니다. 실제 API에서 게시 내용과 기존 이용자 글 보존을 확인합니다.

원고에서 `key`를 제거해도 이미 게시한 글을 자동으로 삭제하지 않습니다. 참여자 답변이 달린 글을 보호하기 위한 규칙입니다. 폐기가 필요한 경우 기존 내용을 명확히 정정하거나 승인된 저장소 관리 절차로 처리합니다.

초기 원고를 구성한 도구는 `execution/prepare_qna_samples.py`입니다. 실제 홈페이지 루트와 검토 초안 JSON을 입력받아 소스 파일·줄번호와 기능 ID를 검사하고 원고를 만듭니다. 초안은 `.tmp/`의 중간 산출물이며 검토 후 게시하는 최종 원고는 위 JSON입니다.

## 검증

`npm run check`는 원고 수·중복·실제 기능 참조·출처 도메인·소스 근거·샘플 표시와 일반 API의 동일한 입력 제한을 검사합니다. 게시 경쟁, 사용자 글 보존, 원고 개정 역행 방지, 게시 실패 시 기존 글 조회 유지 및 안전한 출처 링크를 테스트합니다.

읽기 전용 전수 브라우저 검증은 `execution/qa-qna-samples.cjs`입니다. 운영에서는 기존 글 기준본과 비교하며 게시·수정·삭제 요청을 보내지 않습니다. 로컬 테스트는 `QNA_LOCAL_TEST=1`, `QNA_LOCAL_SAMPLES=1`을 명시한 독립 메모리 미리보기에서 진행합니다. 보고서에는 원고·기존 글 본문이나 작성 권한을 기록하지 않습니다.
