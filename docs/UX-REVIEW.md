# 상담 가이드북 UI/UX 3회 검토

검토일: 2026-10-15 · 대상: 고객을 응대하면서 홈페이지 조치 방법을 안내하는 상담사

기존 `dist/index.html`, `styles.css`, `app.js`, 98개 기능 데이터와 데스크톱·모바일 QA 이미지를 확인했다. 기능의 사실관계는 기존 카탈로그와 개인정보를 가린 캡처를 유지한다. 화면에 없는 성공 조건이나 고객별 이용 가능 여부를 새로 만들어 안내하지 않는다.

## 1차 — 상담 시나리오와 정보구조

**확인한 문제**: 기존 화면은 소개 영역이 크고, 기능 중심의 대분류에서 상담사가 고객 표현을 메뉴명으로 바꾸어 생각해야 했다. 상세 안내에서 로그인 조건·홈페이지 처리 범위와 조치 순서가 한 흐름으로 보이지 않았다.

**결정과 반영**:

- 소개와 장식을 줄여 첫 화면에 검색, 이사·요금·장애·개통의 빠른 질문, 분류와 결과가 함께 보이게 했다.
- 대분류는 왼쪽 탐색, 중·소분류와 대상 상품은 명시적인 필터로 제공한다. 문의 목적은 카탈로그의 실제 action 값으로 생성하므로 ‘납부’ 등 교정 사항이 자동 반영된다.
- ‘처리 가능’이라는 단정 대신 신청·변경/조회/정보 안내/외부 서비스의 **처리 유형**을 표시한다. 실제 제공 여부는 가입상품과 홈페이지 로그인 후 확인하도록 안내한다.
- 상세를 ‘안내 전 확인 → 메뉴 경로 → 고객 조치 순서 → 고객 안내 문구’로 구성한다. 화면에는 실제 캡처, 인증 화면, 로그인 진입, 소스 기반 예시를 각각 표시한다.
- 관련 기능을 상세 아래에 제공한다. 캡처에 임의의 버튼 번호나 확인되지 않은 완료 화면을 추가하지 않는다.

**검토 기준**: 상담사가 고객 질문을 듣고 상품·인증 조건을 확인한 뒤 고객이 실행할 순서를 바로 읽을 수 있는가.

## 2차 — 검색과 결과 선택

**확인한 문제**: 작은 카드의 일반적인 ‘관련 용어’ 표시는 연결 이유가 약했다. 검색을 바꾸어도 기존 필터가 남아 결과가 없어질 수 있었고, 오타·자연어 입력의 추천 경로가 입력창에서 드러나지 않았다.

**결정과 반영**:

- 독립 검색 엔진의 자연어/동의어/초성/오타 결과와 일치 이유를 카드에 표시하고, 제목·설명에 일치한 단어를 안전하게 강조한다.
- 입력창에 자동완성 목록을 붙이고 방향키·Enter·Escape 및 `aria-activedescendant`로 선택할 수 있게 했다.
- 비교 가능한 두 열의 결과 카드에 기능명, 설명, 실제 메뉴 경로, 상품·처리 유형·로그인 조건을 순서대로 배치한다. 과도한 장식보다 읽기와 비교를 우선한다.
- 적용 필터를 해제 가능한 칩으로 표시한다. 0건이면 ‘검색어 유지하고 범위 넓히기’와 짧은 추천 검색어를 제공한다.
- 자유문장 검색어는 메모리에서만 다룬다. URL·localStorage·서버·분석 서비스에 기록하지 않는다. 직접 공유 링크에는 기능 ID만 넣는다.

**검토 기준**: 일치 이유를 보고 잘못된 상품이나 단순 정보 안내를 실제 신청 기능으로 오해하지 않고, 결과가 없어도 검색을 복구할 수 있는가.

## 3차 — 반복 사용과 접근성

**확인한 문제**: 기존 CSS는 작은 화면에서 최근 본 기능 탭을 숨겼고, 보조 텍스트와 클릭 영역이 작았다. 목록 전체 재렌더링 후 즐겨찾기 버튼의 키보드 포커스가 사라질 수 있었다. 제공된 모바일 QA 이미지는 전환 중인 사이드바가 본문 일부를 덮어, 최종 모바일 상태를 증명하기 어려웠다.

**결정과 반영**:

- 즐겨찾기와 최근 본 기능을 데스크톱·모바일 모두 노출하고, 기능 ID만 현재 브라우저에 보관한다.
- 기본 본문은 14px, 안내 단계와 고객 문구는 14px 이상을 사용한다. 검색·메뉴·즐겨찾기의 주요 모바일 조작 영역은 약 44px를 확보한다.
- 검색 단축키 `/`, `Ctrl/Cmd K`, 탭 방향키 이동, 명시적인 포커스 표시와 기본 dialog의 포커스 제어를 제공한다. 즐겨찾기 재렌더링과 상세 닫기 후 관련 버튼으로 포커스를 복원한다.
- 모바일 메뉴의 열린 상태를 `aria-expanded`와 가림막으로 연결한다. 숨겨진 사이드바는 `visibility:hidden`으로 키보드 탐색에서도 제외한다. 최근 탭은 숨기지 않는다.
- 화면 전체 확대와 원본 크기 전환을 제공하며 긴 캡처를 스크롤로 확인할 수 있게 한다. 인쇄 시 메뉴와 도구를 제거하고 선택한 상세 안내만 표시한다.
- 모달 내부 안내 문구 복사는 Clipboard API가 제한되는 환경에서 모달 안에 임시 입력 영역을 두는 대체 복사를 사용한다. 복사 실패도 문구로 안내한다.
- 애니메이션 감소 설정을 존중하며 모바일 QA는 메뉴 닫힘과 전환 종료 후 촬영해야 한다.
- 실제 390/320px 렌더를 확인한 뒤 필터의 초기화 버튼을 마지막 칸으로 배치해 선택 영역을 넓혔다. 한국어 단어가 한 글자씩 다음 줄로 분리되지 않도록 줄바꿈을 조정했다. 검색 중에는 홈 시나리오를 접고, 긴 검색문장의 결과 표시는 72자로 줄여 결과에 빨리 접근하게 했다.

**검토 기준**: 반복 검색·저장·직접 링크 안내가 키보드와 모바일에서도 가능하고, 화면을 확대하거나 인쇄해도 고객 안내 정보가 유지되는가.

## 검증 범위와 한계

이 문서는 검토와 반영 사항을 기록한다. 실제 동작 통과 여부는 별도의 자동 UI 검증 보고서로 판단한다. 원본 홈페이지나 데이터베이스에 연결하지 않았으며 고객 업무를 실행하지 않는다. 캡처 이후 달라진 홈페이지 메뉴와 고객별 이용 가능 여부는 현재 홈페이지에서 최종 확인해야 한다.

## 최종 브라우저 검증과 시각 확인

2026-10-15 최종 빌드를 Edge headless와 엄격한 CSP가 적용된 로컬 정적 미리보기, `file://` 독립 HTML에서 검증했다. `execution/qa-ui.cjs`의 **82개 항목이 모두 통과**했다. 브라우저 실행 오류 0건, CSP 위반 0건, 외부 네트워크 요청 0건이다. 결과 보고서는 `.tmp/ui-qa/report.json`에 재생성된다.

확인한 범위:

- 98개 기능, 4개 홈 시나리오, 동의어·초성·오타·자연어 검색과 검색 이유·강조 표시
- 자동완성의 방향키·Enter·마우스 선택, 대·중·소분류와 상품·인증·처리 유형·문의 목적 필터, 0건 범위 복구
- 즐겨찾기 새로고침 유지, 최근 기능, 탭 방향키 이동, 저장소의 기능 ID 제한
- 고객 조치 순서, 개인정보가 가려진 실제 캡처와 소스 예시의 구분, 문구·메뉴 경로 대체 복사, 기능별 직접 링크, 원본 화면 확대, 선택 가이드 인쇄
- 자유문장 검색어의 URL·로컬 저장소 미기록, HTML 이벤트 주입 방어, 엄격한 웹 CSP와 독립 파일 CSP
- 실제 단일 HTML 다운로드, 98개 캡처 데이터 내장, 외부 리소스 요청 없이 독립 파일에서 자연어 검색·복사·직접 진입
- 390px·320px의 목록·상세 가로 넘침 없음, 모바일 최근 탭, 메뉴의 본문 inert 및 Escape 복구

데스크톱 1440×1100, 모바일 390×844와 320×844, 모바일 상세 캡처를 직접 검토했다. 파일은 `.tmp/ui-qa/desktop.png`, `mobile-390.png`, `mobile-320.png`, `mobile-detail.png`에 생성된다. 모바일 캡처는 상단 스크롤, 메뉴 닫힘, 전환 종료와 이전 복사 알림 종료를 확인한 상태다. 처음 확인된 한국어 한 글자 줄바꿈과 좁은 필터 영역을 보정했고, 최종 화면에서 반영을 확인했다.

검색 회귀 검증에서 발견한 ‘요금재’는 ‘요금제’로 표기를 교정한다. 짧은 오타만으로 모바일이나 변경 업무를 단정하지 않고, 요금제 관련 기능에서 상품과 처리 유형을 비교하도록 유지했다.
