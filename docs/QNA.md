# 상담사 주요 QnA 운영 안내

홈페이지 소스·화면을 기준으로 검토한 98개 가이드는 기존대로 유지합니다. 참여자가 등록한 질문과 답변은 별도 출처로 표시하며, 공식적으로 검토한 홈페이지 가이드로 간주하지 않습니다. 통합 검색과 QnA 메뉴에서 제목·태그·질문·모든 답변 내용을 찾을 수 있습니다. 검색어는 서버에 보내지 않습니다.

## 공유 저장소 연결

Vercel `interview1` 프로젝트의 Storage에서 Blob을 만들 때 **Private**를 선택하고 **Production** 환경에 연결합니다. Vercel이 연결한 `BLOB_STORE_ID` 및 OIDC 또는 `BLOB_READ_WRITE_TOKEN`을 SDK가 서버에서 사용합니다. 토큰은 코드·브라우저·공개 JSON·대화에 넣지 않습니다. 환경변수 연결을 변경했다면 Production을 다시 배포합니다.

Vercel Functions의 OIDC 토큰은 요청 컨텍스트로 제공될 수 있으므로 `VERCEL_OIDC_TOKEN` 환경변수의 존재를 연결 필수 조건으로 삼지 않습니다. 연결된 store ID를 확인하고 실제 인증은 SDK에 맡깁니다. 이 방식은 [SDK의 요청별 토큰 처리](https://github.com/vercel/storage/blob/main/packages/blob/src/vercel-oidc-token.ts)를 따릅니다.

저장 객체는 `qna/state.json`이며, 공개 콘텐츠와 작성자 권한 해시·변경 기록·요청 제한 상태를 함께 보관합니다. Blob URL은 공개 UI에 전달하지 않습니다. `GET /api/qna`는 공개 가능한 필드만 반환하며 캐시하지 않습니다. DB·SQL·Redis·마이그레이션은 사용하지 않습니다.

저장소 연결이 없거나 읽기가 실패하면 준비 중 또는 오류를 알리고 쓰기를 막습니다. 브라우저 임시 저장을 공유 저장으로 대체하지 않습니다. Preview 배포는 읽기 전용입니다. 운영 출처는 `https://interview1-chi.vercel.app`이며 추가 도메인은 서버의 `QNA_ALLOWED_ORIGINS`에 정확한 HTTPS origin으로 지정합니다.

## 작성·수정·삭제

누구나 별도 로그인 없이 질문과 답변을 작성할 수 있습니다. 작성자 이름은 입력한 표시명이며 본인 인증을 뜻하지 않습니다. 고객 이름·연락처·가입번호·인증번호 등 개인정보는 등록하지 않습니다. 명백한 휴대전화번호와 주민등록번호 형식은 서버에서 거부합니다.

처음 글을 등록할 때 브라우저가 32바이트 무작위 소유키를 만들고 서버는 해시만 보관합니다. 이후 같은 브라우저에서 자신의 글을 수정·삭제합니다. 다른 사람의 글은 수정·삭제할 수 없습니다. 브라우저 데이터를 지우거나 다른 기기를 쓰면 기존 글의 작성 권한을 되찾을 수 없습니다. 소유키를 타인에게 공유하면 해당 글의 권한도 공유되므로 외부로 보내지 마세요.

질문과 답변은 각각 버전으로 충돌을 감지합니다. 다른 변경과 충돌하면 원고를 유지하고 다시 불러오도록 안내합니다. 답변이 남아 있는 질문은 삭제할 수 없습니다. 각 작성자가 자신의 답변을 먼저 삭제해야 합니다. 생성 요청은 요청 ID를 이용해 재시도로 인한 중복 생성을 막습니다.

삭제한 글은 공개 응답에서 즉시 제외됩니다. 제한된 내부 삭제 기록(최대 100개)이 보존될 수 있으므로 이 기능은 법적 의미의 완전 삭제나 민감정보 저장 용도로 사용하지 않습니다.

## 운영 범위·유지보수

현재 설계는 소규모 공유 지식 보드입니다. 질문 최대 500개, 질문당 답변 최대 50개, 전체 객체 4MiB, 질문·답변 본문 각각 4,000자로 제한합니다. 제목은 120자, 태그는 8개까지입니다. 한도 도달 시 기존 글은 읽을 수 있으며 새 등록은 안내와 함께 거부됩니다. 대규모 확장이나 별도 관리자 권한·계정 인증은 별도 설계가 필요합니다.

여러 서버에서 동시에 저장해도 이전 글을 덮어쓰지 않도록 Private Blob의 캐시 우회 읽기와 ETag 조건부 쓰기를 사용합니다. 실패 시 제한 횟수만 재시도합니다. 공유 IP당 15분 120회, 작성 키당 15분 30회, 전체 시간당 500회 쓰기를 기본 제한합니다. 원 IP 대신 저장소별 비밀 salt로 만든 HMAC만 제한된 기간 보관합니다. 공유망의 상담사 수에 따라 한도는 코드 검토 후 조정합니다. 공개 익명 작성은 자동화 공격을 완전히 막지 못하므로 필요하면 Vercel WAF를 별도로 구성합니다.

조건부 쓰기용 파일 읽기는 `useCache: false`와 `accept-encoding: identity`를 함께 지정합니다. 압축된 전송 표현의 weak ETag를 원본 쓰기 버전으로 사용하지 않으며, weak/missing ETag는 임의로 보정하지 않고 오류로 처리합니다. 운영에서 파일 크기가 늘어난 뒤 나타난 저장 충돌을 이 경로로 수정하고 연속 등록·수정·삭제를 확인했습니다.

운영 소유자는 Vercel Storage 접근 권한을 가진 담당자입니다. 백업·보존·문제 게시물 처리는 담당자의 승인된 저장소 관리 절차를 사용합니다. 서비스 내 관리자 로그인이나 타인 글 삭제 화면은 제공하지 않습니다. 객체의 권한 해시를 공개 다운로드하거나 Git에 커밋하지 않습니다. Blob의 사용량·요금·보존 정책은 연결한 Vercel 플랜에서 확인합니다.

## 검증

`npm run check`에서 기존 가이드 검증과 QnA 검색·권한·충돌·요청 보안 테스트를 실행합니다. `QNA_LOCAL_TEST=1` 로컬 미리보기는 운영과 분리된 명시적 메모리 저장소를 사용합니다. 재시작하면 테스트 데이터가 사라집니다. 실제 공유 연결은 Production `/api/qna`와 서로 다른 브라우저 컨텍스트의 등록·조회로 확인합니다. 테스트 글은 본인 답변을 삭제한 뒤 본인 질문을 삭제해 정리합니다.

2026-10-15 운영 주소에서 QnA 38개 브라우저 검증을 통과했습니다. 실제 Private Blob에 등록한 질문을 다른 브라우저에서 조회·답변하고, 답변 본문 검색과 작성자별 수정·삭제를 확인했습니다. 기존 가이드 74개 운영 브라우저 검증과 자동 테스트 155개도 통과했습니다. 임시 QA 글과 검증용 정리 코드는 남기지 않았습니다.
