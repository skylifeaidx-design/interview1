# 상담 검색 운영 가이드

이 검색은 기능 목록과 한국어 표현 사전을 브라우저 안에서 비교합니다. 외부 AI API, 데이터베이스, 검색 서버, 검색문장 로그를 사용하지 않습니다. 기능 목록에 있는 화면만 결과로 반환하며, 찾지 못한 업무는 확인되지 않은 것으로 표시합니다.

## 파일과 API

- `src/search.js`: 의도 판단·가중치·필터·초성·자모 비교 로직. 브라우저 `window.GuideSearch`와 Node `module.exports`를 지원합니다.
- `content/search-dictionary.json`: 고객 표현·동의어·상품 단서·지원되지 않은 업무·확인 질문·추천 검색어를 관리합니다.
- `content/features/*.json`: 실제 기능의 제목·별칭·설명과 화면 경로입니다.
- `tests/search.test.cjs`: 실제 기능 데이터와 사전을 함께 읽는 회귀 검증입니다.

```js
const engine = GuideSearch.createEngine(features, dictionary);
const result = engine.search('이사해서 인터넷 설치 장소를 바꾸려고요', {
  major: '', middle: '', minor: '', product: '', login: '',
  availability: '', action: ''
});
// result.items[0].feature: 실제 기능 원본
// result.items[0].reason: 결과 선택 이유
// result.items[0].matchedTerms: 일치한 표현(최대 5개)
const completions = engine.suggest('이전설치');
// [{ text: '설치주소 변경 신청', label: '이용·변경 · TV·인터넷', type: 'intent' }]
```

`search()`는 `{ items, suggestions, normalizedQuery, intent, total, lowConfidence, correction? }`를 반환합니다. 결과 항목은 `{ feature, score, matchType, matchedTerms, reason }`입니다. `intent`는 `{ id, label, product, action, unsupported?, ambiguous? }`입니다. 자동완성은 `{ text, label, type }` 배열을 최대 7개 반환합니다.

대·중·소 분류, 상품, 업무, 기능 유형은 실제 데이터 값과 정확히 일치하는 필터입니다. 로그인은 `required`·`public` 또는 `true`·`false`를 지원합니다. 선택적으로 `scope: [기능 ID]` 또는 `Set`을 넘겨 범위를 제한할 수 있습니다. 빈 검색은 필터 범위의 기능을 우선순위대로 모두 보여줍니다.

## 결과의 우선순위와 설명

1. 정확한 기능명과 등록된 별칭을 우선합니다.
2. 한국어 문장에서 업무 의도를 찾아 실제 대상 화면에 가중치를 줍니다.
3. 상품 단서를 함께 비교합니다. 상품 공통 기능은 유지하며, 사업자 화면은 사업자·법인 단서가 있을 때 우선합니다.
4. `내역·이력·일정`은 신규 신청과 구분합니다. 기능 설명의 단순 단어 일치는 낮게 평가합니다.
5. 초성 입력과 한글 자모의 소규모 편집 차이를 허용합니다. 짧은 오타는 사전 표현과도 비교합니다.

예를 들어 “미납으로 휴대폰이 정지됐는데 돈 내고 풀려면”은 `이용정지 해제·납부`로 연결합니다. “휴대폰을 잃어버렸는데 잠깐 멈추고 싶어요”는 `모바일 일시정지/해제`로 연결합니다. 청구요금과 실시간 이용량, 회원 주소 수정과 설치장소 이전, 상품 소개와 기존 모바일 요금제 변경도 구분합니다.

`정지 해제`와 `주소 변경`처럼 대상이 불분명하면 결과와 함께 `lowConfidence: true` 및 구체화 검색어를 제공합니다. `score`는 순위 계산 값이며 정확도 확률이 아닙니다. UI에는 점수보다 `reason`과 의도 확인 문구를 보여주세요.

## 표현을 추가하는 방법

기존 화면의 별칭만 늘릴 때는 해당 기능 JSON의 `aliases`에 고객 표현을 추가합니다. 문장 전체를 특정 업무로 연결하려면 사전의 `intents`에 표현을 추가합니다.

```json
{
  "id": "relocation",
  "label": "설치장소 이전 신청",
  "action": "이전설치",
  "targets": ["설치주소 변경 신청"],
  "phrases": ["이사", "이전설치", "새집"],
  "excludeAny": ["회원주소", "회원정보"],
  "rules": [
    { "all": [["설치장소", "인터넷설치"], ["이사", "옮기"]], "weight": 30 }
  ]
}
```

`phrases`는 띄어쓰기·대소문자를 무시한 포함 비교입니다. `rules[].all`은 각 묶음에서 하나 이상 일치해야 합니다. `excludeAny`에 포함된 표현이 있으면 해당 의도를 제외합니다. `targets`는 실제 기능 제목과 같아야 합니다. 기능 제목을 변경할 때는 사전의 대상 제목도 갱신해야 합니다.

`replacements`는 `[[원래 표현, 정규화 표현]]`입니다. A/S·eSIM·휴대폰·리모콘 등 표기 차이와 자주 나오는 오타를 관리합니다. 모든 규칙은 문자열 비교로 처리하며 사전 안에 정규식이나 JavaScript를 넣지 않습니다.

미지원 직접 업무는 `unsupported`에 선언합니다. 서비스 해지, 명의변경, TV·인터넷 요금제 변경, TV·인터넷 일시정지 등은 현재 기능 목록에서 직접 처리 화면이 확인되지 않아 결과 0건과 실제 지원 안내 검색어를 반환합니다. `부가서비스 해지`와 `해지 서류`는 기존 가입내역·서류 화면으로 연결할 수 있도록 예외를 둡니다. 향후 실제 화면을 추가할 때는 기능 원본과 증빙 화면을 먼저 준비하고 미지원 규칙을 함께 갱신하세요.

## 검증과 제한

```sh
node --test tests/search.test.cjs
```

검증에는 자연어 상담 66개, 미지원 직접 업무 9개, 무관한 검색어, 모호한 요청, 전체 기능명 98개, 상품·로그인·분류·기능 유형 필터, 한글 자모 오타, 사전 확장, 브라우저/Node 공통 실행, 입력 무결성, HTML·정규식 모양 입력이 포함됩니다. 사전이나 기능을 수정한 후 검색 회귀 검증과 프로젝트의 전체 검증을 실행하세요.

이 엔진은 사전과 규칙으로 동작합니다. 임의의 긴 대화, 복잡한 부정·조건문, 새 은어의 의미를 모두 이해하지는 않습니다. 일부 부정 표현은 사전의 제외 조건으로 처리합니다. 검색문장은 최대 500자로 제한하며 원본 검색문장이나 개인정보를 자동 수집하지 않습니다. 빠진 고객 표현은 개인정보를 제거한 예시와 기대 기능을 테스트에 추가한 뒤 사전을 갱신하는 방식으로 개선합니다.
