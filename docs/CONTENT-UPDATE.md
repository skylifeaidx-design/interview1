# 가이드북 수정·검토·배포

상담 기능 설명은 `content/features/`의 기능별 JSON, 고객 표현은 `content/search-dictionary.json`, 화면은 `public/screens/`에서 관리합니다. 화면 디자인을 수정할 때만 `src/`를 변경합니다.

## GitHub에서 간단히 수정하기

1. 수정할 기능의 JSON 파일을 열어 연필 아이콘으로 편집합니다. 기존 기능의 `id`는 공유 링크에 쓰이므로 유지합니다.
2. `title`, `summary`, `menu`, `steps`, `script`를 실제 홈페이지와 대조합니다. 대·중·소 분류는 `major`, `middle`, `minor`입니다.
3. `availability.reviewedAt`을 실제 확인일로 갱신합니다. 화면도 새로 캡처했다면 개인정보를 가린 뒤 파일을 교체하고 `screen.captured`를 갱신합니다.
4. 새 브랜치에서 변경을 제안하고 Pull Request를 만듭니다. 자동 검증과 연결된 Vercel Preview에서 검색·안내·화면을 확인합니다.
5. 검토한 변경을 `main`에 병합하면 연결된 Vercel 프로젝트가 운영 배포를 생성합니다. 배포 성공을 확인한 뒤 운영 주소를 열어 수정한 기능을 점검합니다.

JSON은 큰따옴표와 쉼표 규칙을 지켜야 합니다. 마지막 항목 뒤에 쉼표를 넣지 않습니다. 필수 내용·링크·화면 파일이 잘못되면 자동 검증에서 배포를 멈춥니다.

## 검색 표현 추가하기

상담 중 자주 나오는 표현은 검색 사전의 해당 `terms` 또는 `replacements`에 추가합니다. 고객의 실제 이름·전화번호·계약번호·상담 원문은 기록하지 않습니다. ‘요금재 → 요금제’ 같은 오타와 일반적인 고객 표현만 등록합니다.

서로 다른 업무를 같은 표현에 강제로 연결하지 않습니다. 예를 들어 미납 정지 해제와 분실에 따른 일시정지는 구분합니다. 홈페이지에서 직접 처리할 수 있는지 확인되지 않은 업무는 기존 기능으로 꾸며 안내하지 않습니다. 검색 동작이 달라지면 `tests/search.test.cjs`에 실제 기대 결과를 추가합니다.

## 화면 추가·교체하기

화면 파일은 개인정보를 가린 JPEG 또는 PNG를 사용하고 `screens/영문파일명.jpg` 형태로 참조합니다. 실제 캡처(`live`, `authenticated`), 로그인 진입(`login`), 소스 기반 예시(`source`) 구분을 유지합니다. 소스 예시는 캡션에 가상·예시임을 명시합니다.

한 기능에 대표 화면 한 장과 실제 조치 순서를 제공합니다. 고객마다 다른 금액·계약정보·처리 결과를 화면 예시와 동일하다고 보장하지 않습니다.

## 문제가 생겼을 때

문구나 검색 변경은 GitHub에서 해당 커밋을 되돌리는 PR로 복구합니다. 급한 배포 장애는 Vercel에서 직전 정상 배포로 롤백한 뒤 원인을 수정합니다. 이전 인터뷰 사이트의 소스는 `archive/interview-site-20261015` 브랜치에서 확인할 수 있습니다.

운영 공유에는 Vercel의 **Production Domain**을 사용합니다. 배포별 미리보기 주소에 로그인 보호가 적용되어 있다면 일반 공유용 주소와 구분합니다. 공개 페이지에는 마스킹한 화면만 올립니다. 이 가이드북은 고객 데이터베이스나 상담 기록을 수집하지 않습니다.
